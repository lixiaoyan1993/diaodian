# 首页搜索与筛选改造设计

日期：2026-07-08

## 目标

本次改造聚焦首页的“搜索”和“筛选”体验，解决两个核心问题：

1. 用户进入首页后，不清楚应该先搜索还是先筛选。
2. 当前筛选入口过重、层级偏深，首页第一屏被过多条件打断。

本次不调整业务能力范围，重点是重新组织入口优先级，让首页更像“找点起点页”，而不是把所有工具同时摊开。

## 设计结论

采用“搜索作为主入口，筛选作为辅助收窄”的结构。

用户路径调整为：

1. 首页先通过搜索入口进入搜索页，或者先用城市/钓法做一层快速限定。
2. 搜索页默认展示热门搜索和搜索历史。
3. 用户输入关键词或点击热门词后进入结果列表页。
4. 结果页继续承接轻量筛选，复杂细筛统一进入“更多筛选”。

## 首页结构调整

首页顶部区域改为四层结构。

### 1. 第一行：核心控制行

保留以下能力：

- 城市入口
- 地图/列表切换
- 记点按钮

这三个入口保留现有能力，但视觉上压缩成更清晰的一行，减少对地图首屏空间的占用。

### 2. 第二行：主搜索入口

首页搜索条升级为首要操作入口。

- 文案统一为：`搜索标点 / 鱼种 / 标签`
- 点击后进入独立搜索页
- 不在首页内直接承担完整输入和结果逻辑

这样用户一眼就能理解“找点先点这里”。

### 3. 第三行：轻量筛选行

首页仅保留高频、低认知成本的筛选项：

- 钓法
- 离我最近
- 更多筛选

说明：

- `钓法` 保留为首页级快速粗筛
- `离我最近` 保留为首页级快捷能力，便于快速找附近点
- `更多筛选` 作为鱼种、标签等细筛的统一入口

### 4. 第四行：当前条件摘要

不再把所有已选条件平铺成大量 chips，而是压缩成一条摘要信息，例如：

`北京 · 路亚 · 已筛 2 项`

右侧保留 `清空` 操作。

这样既能让用户知道当前状态，又不会让首页第一屏过度拥挤。

## 首页下沉内容

以下内容不再放在首页第一屏：

- 热门搜索整块
- 大量鱼种前置条件
- 大量标签前置条件
- 过多并列条件 chip

这些内容并不是“开始找点”的第一步，继续放在首页会稀释搜索主入口的优先级。

## 搜索页结构

搜索页承担“真正开始找”的任务，结构分为两种状态。

### 1. 默认状态

当用户刚进入搜索页且未输入关键词时，展示：

- 顶部固定搜索框
- 热门搜索
- 搜索历史

要求：

- 搜索历史支持单条删除
- 搜索历史支持清空
- 热门搜索样式沿用首页卡片语言，但视觉密度更轻

### 2. 结果状态

当用户输入关键词或点击热门词后，搜索页进入结果态。

结果态只展示列表，不在搜索页混入地图视图。

结果页顶部保留轻量筛选：

- 城市
- 钓法
- 更多筛选

这样可以在不返回首页的情况下继续收窄结果。

## 筛选体系重组

筛选能力按“粗筛优先、细筛下沉”的原则重组。

### 首页负责

- 城市
- 钓法
- 离我最近

### 更多筛选负责

- 鱼种
- 标签

后续若新增收费、停车、夜钓、深浅、水质等条件，也统一进入“更多筛选”，避免首页再次膨胀。

## 页面职责边界

### 首页

负责进入找点流程、查看地图分布、进行最少量的快速粗筛。

### 搜索页

负责从关键词开始找点，并承接热门词、历史词和搜索结果。

### 更多筛选页

负责管理鱼种、标签等细筛条件，不承担搜索主入口职责。

## 交互结果预期

改造后，用户的理解模型应变成：

- 想找具体点：先搜索
- 想限制城市：切换城市
- 想先缩小钓法范围：点钓法
- 想找附近：点离我最近
- 想要更细：进更多筛选

这样首页、搜索页、筛选页三者职责清晰，不会再把“搜索、筛选、结果”混在同一层里竞争注意力。

## 实施范围

本次改造优先涉及：

- `client/src/pages/hall/hall.vue`
- 现有搜索页相关逻辑与样式
- 首页筛选入口与筛选状态摘要

如现有搜索页结构不足以承接热门搜索/历史/结果态，需要在现有页面基础上补齐，但不新增无关能力。

## 验收标准

1. 首页第一屏能明确看出“搜索是主入口”。
2. 首页不再展示热门搜索整块。
3. 首页不再平铺鱼种和标签作为主操作。
4. 搜索页默认展示热门搜索和搜索历史。
5. 搜索结果仅展示列表，并支持继续轻筛。
6. 首页筛选状态改为摘要表达，不再依赖大量已选 chips。
